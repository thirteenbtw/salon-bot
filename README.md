# Бот записи для салона (маникюр, педикюр и т.п.)

Telegram-бот: клиент выбирает услугу, дату и время, получает подтверждение и напоминание за сутки.
У мастера есть расписание и отмена записей.

**Стек:** Python 3.12, aiogram 3, SQLite (файл в `./data`), Docker.

## 🔗 Демо

> **Ссылка на бота:** [@thirteenbtwsalonbot](https://t.me/thirteenbtwsalonbot)

Как попробовать:
1. Откройте бота, нажмите **/start** → **💅 Записаться** → услуга → дата → время → **Подтвердить**.
2. **📋 Мои записи** — просмотр и отмена своей записи.
3. Чтобы увидеть сторону мастера, отправьте боту **/master** (работает только в демо-режиме) —
   внизу появятся кнопки **📅 Сегодня / 📅 Завтра / 🗓 Другая дата**. Под каждой записью есть кнопка
   «❌ Отменить»; клиент получит уведомление об отмене. Выйти из режима мастера — **/client**.
4. Совет: запишитесь с одного аккаунта, а мастером сделайте другой — так видно обе стороны.

## Что умеет

**Клиент**
- Запись в 4 касания кнопками, без ввода текста: услуга → дата → время → подтверждение. На любом шаге можно вернуться назад.
- Показываются только реально свободные даты и время (с учётом длительности услуги, выходных, часов работы).
- Двойное бронирование исключено (повторная проверка при подтверждении + блокировка в БД).
- При первой записи бот просит поделиться номером телефона (кнопка «📱 Поделиться номером», можно пропустить); номер запоминается.
- «Мои записи», отмена с подтверждением.
- Напоминание за 24 часа с кнопкой отмены (если записались менее чем за сутки — не присылается).

**Мастер** (`MASTER_IDS` или `/master` в демо-режиме)
- `/today`, `/tomorrow`, `/schedule [дата]` — расписание (или кнопки внизу).
- Кнопка «Отменить» под записью или `/cancel <номер>`; клиенту уходит уведомление.
- В расписании и в уведомлениях у каждой записи: имя клиента ссылкой на его профиль в Telegram
  (`@username`; если username нет — ссылка по ID) и номер телефона, если клиент им поделился.
- Мастеру приходят уведомления о новых записях и отменах клиентов.
- `/client` — выйти из режима мастера (только в демо-режиме; мастера из `MASTER_IDS` меняются в `.env`).

## Как устроено

```
app/
  main.py             запуск: бот, диспетчер, фоновая задача напоминаний
  handlers_client.py  сценарий клиента: меню, запись, «Мои записи», отмена
  handlers_master.py  команды мастера: расписание, отмена, режим демо
  slots.py            расчёт свободных дат и времени
  db.py               SQLite (aiosqlite): услуги, записи, мастера
  reminders.py        цикл раз в минуту: напоминания за 24 часа
  texts.py, config.py форматирование и настройки из .env
tests/                тесты слотов, защиты от двойной записи и напоминаний
```

- Бот работает через long polling: публичный адрес и открытые порты не нужны.
- Время записей хранится как локальное время салона (`TZ`), без пересчёта часовых поясов.
- Двойная запись исключена на двух уровнях: слот проверяется при подтверждении, а вставка в БД идёт под блокировкой.
- Сценарий клиента построен на inline-кнопках, поэтому ничего печатать не нужно.

## Запуск на сервере (Docker)

Нужен сервер с Docker и Docker Compose. Публичный IP/домен и открытые порты **не нужны** —
бот работает через long polling.

1. Создайте бота у [@BotFather](https://t.me/BotFather) (`/newbot`) и скопируйте токен.
2. На сервере:
   ```bash
   git clone https://github.com/thirteenbtw/salon-bot.git && cd salon-bot
   cp .env.example .env
   nano .env            # BOT_TOKEN, SALON_NAME, SALON_ADDRESS, TZ, часы работы...
   docker compose up -d --build
   docker compose logs -f
   ```
3. База лежит в `./data/salon.db` (том Docker) — переживает перезапуск и обновление.
   Старые базы обновляются сами: недостающие колонки (`username`, `phone`) добавляются при запуске.

Обновление: `git pull && docker compose up -d --build`.

> **Про сеть.** В `docker-compose.yml` указано `network_mode: host`: бот не слушает портов, ему нужен только
> исходящий доступ к Telegram. На части VPS обычная bridge-сеть Docker не выходит в интернет, с host-режимом
> это не мешает. Если у вас bridge работает штатно, обе строки с `network` можно удалить.

## Настройки (`.env`)

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | токен от BotFather |
| `MASTER_IDS` | Telegram ID мастеров через запятую (свой ID — команда `/id`) |
| `DEMO_MODE` | `true` — любой может стать мастером через `/master`. **Для боевого режима — `false`** |
| `TZ` | часовой пояс салона, напр. `Europe/Moscow` |
| `WORK_START`, `WORK_END` | часы работы |
| `SLOT_STEP_MIN` | шаг сетки времени, мин |
| `DAYS_AHEAD` | на сколько дней вперёд открыта запись |
| `DAYS_OFF` | выходные, 0=пн … 6=вс |

Услуги (название, длительность, цена) создаются при первом запуске из `app/config.py` (`DEFAULT_SERVICES`).
Изменить позже — правкой таблицы `services` в `data/salon.db` (например, `sqlite3 data/salon.db`).

## Тесты и локальный запуск без Docker

```bash
pip install -r requirements.txt pytest pytest-asyncio
python -m pytest
BOT_TOKEN=... DB_PATH=data/salon.db python -m app.main
```

## Ограничения (осознанно, для MVP)

- Один мастер / одно расписание (записи не пересекаются в принципе). Несколько мастеров — следующий этап.
- Услуги редактируются в БД, а не командами бота.
- SQLite достаточно для одного салона; переход на PostgreSQL потребует замены слоя `app/db.py`.
